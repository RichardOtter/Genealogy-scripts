SECTION RULES
Sections are separated by an exact delimiter consisting of 73 "=" characters followed by "DIV80==".
Any line containing "DIV80==" that does not match the exact delimiter is considered a corrupted delimiter.
Each section must begin with four required header lines in this exact order: PID, Coord, Place, Stones.
If the PID line is "===PID: IGNORE_SECTION", the section is skipped entirely.

STONES HEADER RULES
The Stones value may be 0-V, N, or N-V, where N is an integer greater than or equal to 1.
The value 0-V is the only valid representation of zero stones.
Values such as 0, 0-, -V, V, or any malformed form are invalid.
The -V suffix indicates the grave site is currently vacant.
The integer portion indicates the number of stones historically present.
Vacancy semantics for N-V are accepted but not yet validated.

ZERO-STONE RULES (Stones = 0-V)
No stone blocks may appear in a 0-V section.
A 0-V section must contain at least one dated-entry set.
A dated-entry set may contain any combination of the lines ===Date:, ===Photos:, ===Notes:.
Each line in the set is optional, but at least one must be present.
Multiple dated-entry sets are allowed.

NUMBERED STONE RULES (Stones = N or N-V)
The number of numbered stone blocks must match the integer N.
Stone numbers must be consecutive and strictly decreasing.
Stone numbers must be integers greater than or equal to 1.
VACANT stones are allowed and do not require Date or Transcription blocks.

STONE BLOCK STRUCTURE RULES
Each numbered stone must contain ===Date: immediately after the stone header.
Each numbered stone must contain ===Transcription: immediately after the Date line.
Each transcription block must contain an exact begin marker line.
Each transcription block must contain an exact end marker line.
There must be at least one non-empty line of text between the begin and end markers.

DATED-ENTRY SET RULES FOR NUMBERED STONES
Each numbered stone must contain at least one dated-entry set.
A dated-entry set begins with ===Date:.
The next line must be ===Photos: with no intervening lines.
After ===Photos:, any number of text lines are allowed.
A dated-entry set must contain at least one ===Notes: line somewhere after ===Photos:.
Text lines after ===Notes: are allowed.
A dated-entry set continues until the next ===Date: or the next ===Stone:.
Multiple dated-entry sets are allowed.

POST-STONE METADATA RULES
After all stone blocks, the section must contain exactly one set of the following lines in this order:
===Interpretation:
===Location:
===Table:
===Status:

SECTION COLLECTION RULES
Sections are collected between delimiters.
A final section without a trailing delimiter is still processed.

OUTPUT RULES
All validation errors are collected and printed.
If no errors are found, the validator reports success.
