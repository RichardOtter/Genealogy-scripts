Purpose

This utility is designed to update a citation's CitationName in a bulk
operation. First, a set of filters is specified and applied to limit which
citations will be modified, then rules are followed to determine the new
Citation Name. If the results look satisfactory, the utility is then instructed
to actually save the changes to the database.

This utility will work in versions 8 and later of RootsMagic database. It is
aware of the new option in v12 that allows users to create their own custom 
CitationName template. 

=========================================================================DIV80==
█_INCLUDE: REUSE_LIB_BACKUPS_SMALL_CHANGES
In addition, this utility can only change citation names. Citation names are
derived from the citation data. If the first result does not give the desired
result, a second run can fix it. No genealogical data can be modified or lost
running this utility.

Now examine the [FILTER] section of the config file:

[FILTER]
USE_REGEXP = off
SOURCE_TEMPLATE = 
SOURCE_NAME = 
CITATION_NAME =

These settings determine which CitationNames will be updated.

First, for now, leave USE_REGEXP = off
The setting is explained in the Notes section below.
REGEXP (regular expressions) allow the use of very sophisticated wild card characters
so allow selection and exclusion of items.

SOURCE_TEMPLATE
allows specification of a particular SourceTemplate name.
If you leave it blank, as it is, then there will be no selection based on
source templates and all citations, no matter which source template was used to 
create their source will be considered.

SOURCE_NAME = 
allows specification of a particular Source name.
If you leave it blank, as it is, then there will be no selection based on
source name and all citations, no matter which source the citation is part
of will be considered.

CITATION_NAME =
allows specification of a particular existing citation name.
If you leave it blank, as it is, then there will be no selection based on
the existing citation name and all citations will be considered.

Here is an example to make this more concrete,
Say that You have a source template which you have modified by adding a 
CitationName template to the details of the template as can be done in RM12.
New citations will use the template, but existing ones are not changed and still
use the default template. (a semicolon separated list of all citation data items
in the order they are listed in the SourceTemplate.)
Let's assume that you have created several source using that Source Template.
If you want to change the citation name for all of them, specify the source 
template name. 
If you want to change only some of the sources, then specify the source name.
Since they all use the same source citation, you don't need to give the source
template name.
Specifying the Citation Name is an option that you probably will not use.


Now come the section with parameters that tell the utility what format to use
to update the citation names.

[CITATION_NAME_UPDATER]
MAKE_CHANGES = off
TEMPLATE_DEFAULT = on
TEMPLATE_FROM_SOURCE_TEMPLATE = 
CUSTOM_TEMPLATE = 

MAKE_CHANGES  on or off
The first is not really a format issue, but whether any changes should be made.
Always leave this off for the first run. It will generate a report that will
tell you how well you have specified the Filter options.
It will also list the default template for all source templates encountered.
This bit of text will be very helpful when writing your own templates as it
gives the names of all the citation data fields.

TEMPLATE_DEFAULT  on or off
If on, then the default template defined by the citations name's source template
is used to update the citations selected by the FILTER section parameters. 
It overrides the parameters TEMPLATE_FROM_SOURCE_TEMPLATE  and CUSTOM_TEMPLATE.

If TEMPLATE_DEFAULT is off, the the other options are considered.

TEMPLATE_FROM_SOURCE_TEMPLATE = on overrides the next option, CUSTOM_TEMPLATE
so that it is not considered

TEMPLATE_FROM_SOURCE_TEMPLATE = on means that for each citation, its source
template is examined. If the source template has a RM v12 custom template
defined (or at least the value in non-blank), then it will be used for all its
citations. 
If the source template does not have a citation name template, then the citation
name is changed to blank.

CUSTOM_TEMPLATE may be set to a text string. 
This is only considered when TEMPLATE_FROM_SOURCE_TEMPLATE is off.
Since only a single template can be specified in the config file, this
should be used only when the filtering includes one source template.



Values in config file sections [FILTER] and [CITATION_NAME_UPDATER] may be
in quotes. if needed. Only necessary if the Template, Source of Citation Name 
has a leading or trailing space character.

Notes

===========-
The utility can operate in a Preview mode in which the database is not altered.
Running the utility in this mode allows one to work on the filter options to 
determine the correct set of citation names to update.
It also displays, in the report, the default citation name template for each 
SourceTemplate under consideration. This default template lists all citation 
dta fields and is of great assistance when writing your own template.

Note that the value can have embedded spaces.
Space characters between the = and the value are ignored.

USE_REGEXP = on

This requires that the REGEXP_PATH be set to a SQLite extension library that
implements RegExp matching.

A popular example is the file regexp.dll from the GitHub repo-
https://github.com/nalgeon/sqlean/releases/latest

The current version is 0.29.0, but future versions should also work.
Open the link, scroll to the bottom of the page to the "Assets" section.
Click on the item named- "sqlean-win-x64.zip"
Save the file on your computer.
Open the zip file and copy the regexp.dll file to a folder on your computer
and then edit the config file so that REXP_PATH points to it.


RegExp examples

using the SOURCE_NAME as an example-
string
This will match any source that has "string" someplace within the source name.

Either of 2 strings match, the strings only need to occur in the name
(name1|name2)

select all Source except those that contain string1
^(?!.*string1).*$

exclude if contains string1 or string2
^(?!.*(string1|string2)).*$

exclude if contains a YYYY > 1900
^(?!.*(190[1-9]|19[1-9][0-9]|[2-9][0-9]{3})).*$

Limiting which Facts are changed

There maybe situations in which only a subset of Facts should be changed to a
new fact type. One can limit the facts by fields that describe them- 
the Description and the Date-

Some examples-

[SOURCE_FILTER]
DESC              = %New York%
DATE              = 1930

if you want to convert only facts whose descriptions start with the
words "New York", then enter-

[SOURCE_FILTER]
DESC              = New York%
DATE              =

notice the trailing percent sign.
If the fact descriptions should only contain "New York" somewhere in the text,
enter-

[SOURCE_FILTER]
DESC              = %New York%
DATE              =

The percent sign % wildcard matches any sequence of zero or more characters.
The underscore _ wildcard matches any single character.

To limit the facts converted by their Date, use the DATE value.
The DATE value is always a four digit year.
For example-

[SOURCE_FILTER]
DESC              = 
DATE              = 1930

The values for DESC and DATE are optional. If all facts of a certain type are to be converted,
leave these fields blank-

[SOURCE_FILTER]
DESC              = 
DATE              =
